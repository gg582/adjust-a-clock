# clockrate — 녹음으로 맞추는 기계식 시계

휴대폰으로 녹음한 시계 소리로 **하루 몇 초 빠르고 느린지**와 **진폭**을 재고, **조속 레버를 어느 쪽으로 얼마나 옮길지** 알려 줍니다.
녹음할 때마다 결과가 기록에 쌓이고, 직전 녹음과 비교해 "그때 옮긴 거리의 몇 배를 어느 쪽으로" 옮기면 되는지 계산합니다.

Slava 5671(18000 bph) 자명종을 조정하면서 만들었지만, 틱 소리가 나는 기계식 시계라면 어떤 것에도 쓸 수 있습니다(`--bph`로 진동수 지정).

## 설치

[ffmpeg](https://ffmpeg.org/)가 필요합니다 (`sudo apt install ffmpeg`, `brew install ffmpeg` 등).

```bash
pip install -e .            # clock-rate 명령 설치
pip install -e '.[test]'    # 테스트까지
```

설치하지 않고 `python3 -m clockrate ...` 로 실행해도 됩니다.

## 시계 맞추는 순서

```bash
clock-rate 녹음1.m4a      # 1. 1분 이상 녹음해서 분석
                          # 2. 안내대로 조속 레버를 옮기고 다시 녹음
clock-rate 녹음2.m4a      # 3. 직전 녹음과 비교해 다음 이동량 안내
...                       # 4. '◎ 조정 완료'가 나올 때까지 반복
```

터미널과 `results/<파일명>/요약.txt`에는 이런 요약이 나옵니다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 시간조정2.mp3   (녹음 64초 · 18000 bph 기준)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 ✖ 크게 어긋남   하루 3분 47초 빠름   (+227.1 ± 4.0 초/일)

 ▶ 할 일
   조속 레버를 느림(-, S) 쪽으로 옮기세요.
   직전 녹음(시간조정) 대비 -115.6 초/일 변화 →
   직전에 옮긴 방향으로, 그때 옮긴 거리의 약 2.0배 더 옮기세요.

 ▶ 이대로 두면
   1일 +3분 47초 · 1주 +26분 29초 · 30일 +1시간 54분

 ▶ 시계 상태
   비트 에러     2.9 ms  ◎ 양호
   진폭          약 298° (288–314°, 틱 308° · 톡 289°)  ◎ 좋음
                 리프트각 52° 가정 — 같은 시계끼리 비교할 때 가장 정확
   속도 안정성   +222 ~ +236 초/일 (10초 단위, 폭 14)  안정

 ▶ 측정 신뢰도  높음
   틱 320/320개 사용 (100%), 놓친 틱 1개 다시 찾음, 잡음 클릭 1개 제외
   틱 시각 흔들림 354 µs · 실측 진동수 18047.3 bph
```

### 판정 기준

| 표시 | 하루 오차 | 뜻 |
|---|---|---|
| ◎ 조정 완료 | ±10초 이내 (`--허용`으로 변경) | 더 건드리지 마세요 |
| △ 미세 조정 권장 | ±30초 이내 | 아주 조금만 옮기세요 |
| ▲ 조정 필요 | ±60초 이내 | |
| ✖ 크게 어긋남 | 그 이상 | |

- **비트 에러**는 틱과 톡 간격의 비대칭입니다. 3 ms 이하면 양호, 5 ms를 넘으면 밸런스 정지 위치(비트)를 맞추는 게 좋습니다.
- **진폭**은 밸런스가 한 번에 도는 각도입니다. 330° 초과는 너무 큼(뱅킹 주의), 250–330° 좋음, 200–250° 보통, 200° 미만은 낮음(태엽 감김·주유·오염 확인)으로 판정합니다(손목시계에서 흔히 쓰는 기준). 아래 [진폭](#진폭) 참고.
- **속도 안정성**은 녹음을 10–20초씩 잘라 따로 계산한 값의 폭입니다. 폭이 크면 태엽이 풀려 가거나, 시계가 흔들렸거나, 녹음 상태가 나쁜 것입니다.
- **측정 신뢰도**는 녹음 상태(길이, 틱 검출률, 잡음 클릭)만으로 판단합니다. "낮음"이면 이유와 함께 녹음 요령을 알려 줍니다.
- **다음 이동량**은 레버를 옮긴 거리만큼 속도가 비례해서 바뀐다고 가정한 추정입니다. 직전 녹음과 차이가 거의 없으면 레버가 헛돌거나 헤어스프링이 레버 핀에서 빠졌을 수 있다고 알려 줍니다.

## 출력

| 파일 | 내용 |
|---|---|
| `results/<파일명>/리포트.png` | 판정과 할 일, 목표 범위 게이지, 타임그래퍼, 시간대별 오차가 한 장에 |
| `results/<파일명>/요약.txt` | 위의 요약 |
| `results/<파일명>/요약.json` | 같은 내용의 기계용 데이터 |
| `results/조정기록.png` | 녹음한 순서대로 하루 오차와 진폭이 어떻게 바뀌었는지, 다음 할 일 |
| `results/조정기록.json` | 조정 기록 (같은 파일을 다시 분석하면 제자리에서 갱신) |
| `results/<파일명>/진단.png`, `소음제거.wav` | `--진단`을 줬을 때만: 소음 제거, 틱 검출 상태, 진폭 계산에 쓴 언락·드롭 위치 |

**타임그래퍼 읽는 법:** 틱마다 규격보다 얼마나 앞섰는지(ms)를 점으로 찍습니다.
- **선의 기울기:** 점들이 위로 올라가면 빠르고, 아래로 내려가면 느립니다.
- **회색 부채꼴:** 목표 범위(±10초/일)입니다. 선이 이 안에 누우면 목표 범위입니다.
- **두 줄의 간격:** 틱(파랑)과 톡(주황) 두 줄 사이의 간격이 비트 에러입니다.

## 옵션

| 옵션 | 값 | 설명 |
|---|---|---|
| `--bph` / `--vph` | `18000` (기본) | 규격 진동수. 다른 시계는 `28800` 등으로 지정 |
| | `자동` | 측정값에서 ±1% 이내의 표준값(3600–36000)을 자동 선택 |
| `--리프트각` / `--lift-angle` | `52` (기본) | 진폭 계산용 리프트각(도). `0`이면 진폭 계산 안 함 |
| `--허용` / `--tolerance` | `10` (기본) | 이 안(초/일)이면 조정 완료 |
| `--분할` / `--split` | `없음` (기본) | 녹음 전체를 한 구간으로 |
| | `자동` | 녹음 **도중** 레버를 민 경우, "스윽" 소리를 찾아 앞뒤를 나눠 비교 |
| | `3.5,9.2` | 지정한 시각(초)에서 나눔 |
| `--기준` / `--reference` | `자동` (기본) | 규격 기준 절대 오차 (`--bph 자동`에서 규격을 못 찾으면 구간 1 기준) |
| | `규격` | 규격 기준 절대 오차 |
| | `구간1` | 첫 구간 대비 변화만 비교 (레버 위치별 효과 확인용) |
| `--이름` / `--names` | `가운데,빠르게,...` | 구간 이름 |
| `--창` / `--window` | 초 | 시간대별 오차 창 길이. 생략하면 10초(구간 90초 미만) 또는 20초, `0`이면 끔 |
| `--출력` / `--out` | 폴더 | 결과 폴더 (기본 `./results`). 조정 기록도 여기에 쌓입니다 |
| `--기록끔` / `--no-history` | | 조정 기록에 남기지 않고 직전 녹음과 비교하지도 않음 |
| `--진단` / `--diagnostics` | | 진단 그래프와 소음 제거 wav도 저장 |
| `--그래프없음` / `--no-plots` | | 요약만 만듦 |

여러 파일을 한 번에 넣으면 적은 순서대로 분석해 기록에 쌓습니다: `clock-rate recordings/시간조정*.mp3`

레버 위치별 효과를 한 녹음으로 비교하려면: `clock-rate 탈진기.mp3 --분할 자동 --기준 구간1 --이름 가운데,한쪽끝,반대쪽끝`

## 진폭

한 번의 틱 소리 안에는 작은 소리가 여러 개 겹쳐 있습니다. 스위스 레버 탈진기(Slava 5671 포함)에서는 **언락**(탈진기가 풀리는 작은 소리) 뒤에 **드롭**(톱니가 떨어지는 큰 소리)이 옵니다.
밸런스가 리프트각만큼 도는 동안이 이 두 소리 사이이므로 진폭을 계산할 수 있습니다.

```
진폭 = 리프트각 / (2·sin(π · 언락→드롭 시간 / 한 주기))
```

- **평균 곡선:** 틱·톡마다 녹음 전체의 소리 크기 곡선을 겹쳐 중앙값을 내고, 드롭 앞에서 물리적으로 가능한 범위(진폭 140–380°에 해당하는 시간)의 가장 뚜렷한 봉우리를 언락으로 봅니다.
- **신뢰도:** 틱을 무작위로 다시 뽑아 계산하는 부트스트랩으로 95% 범위를 구합니다. 틱·톡 값이 30° 넘게 다르거나 범위가 40°보다 넓으면 "참고용"으로 표시합니다.
- **리프트각:** 무브먼트 고유값입니다. Slava 5671의 공식 값은 찾지 못해서, 스위스 레버에 흔한 52°를 기본값으로 둡니다. 절대값은 이 가정만큼 불확실합니다.
- **같은 시계끼리 비교:** 진폭은 리프트각에 거의 비례하므로, 같은 시계의 녹음끼리 비교(진폭이 줄었는지)는 리프트각과 무관하게 정확합니다. 조정 기록 그래프에서 이 추세를 볼 수 있습니다.
- **진단 그래프:** `--진단`을 주면 실제로 어느 소리를 언락·드롭으로 잡았는지 볼 수 있습니다.

## 녹음 요령

- 조용한 방에서 휴대폰 마이크를 시계 뒷면에 바짝 대세요.
- **1분 이상** 녹음하세요. 20초보다 짧으면 정밀도가 크게 떨어지고 속도 안정성도 볼 수 없습니다.
- 자세(문자판 위/세움)와 태엽 감긴 정도에 따라 하루 수십 초까지 달라질 수 있습니다. 비교하는 녹음끼리는 조건을 맞추세요.

## 동작 원리

1. **소음 제거:** 3.5–16 kHz 대역통과 후 스펙트럴 게이팅을 적용합니다. 잡음 기준은 틱 사이 조용한 부분에서 잡습니다.
2. **박자 간격 추정:** 소리 크기 곡선(신호처리 용어로 "포락선", envelope)의 봉우리 간격 중 가장 많이 나오는 값을 씁니다. 틱이 강·약으로 반복돼도 여러 박을 한 박으로 착각하지 않습니다.
3. **1차 틱 검출:** 소리 크기 곡선이 봉우리 높이의 30%를 처음 넘는 시각을 잡습니다.
4. **박 번호 매기기와 잡음 제거:** 틱을 하나씩 따라가며 박 번호를 매기고, 박자에서 벗어난 잡음 클릭은 뺍니다.
5. **정밀 보정:** 틱·톡별 평균 모양(템플릿)을 만들어 각 틱과 상호상관해 시각을 서브샘플 정밀도로 다시 잡습니다. 놓친 틱은 예측 위치에서 템플릿과 충분히 닮은 소리(상관 0.6 이상)를 찾아 채웁니다. 잡음이 많은 녹음에서 틱 시각 흔들림이 약 60% 줄어듭니다.
6. **박자 모델:** `t = a + n·박간격 + c·(홀짝)` 을 최소제곱으로 풉니다. 홀짝 항이 비트 에러입니다.
7. **진폭:** 원본(게이팅 전) 소리에서 언락→드롭 시간을 재어 계산합니다 (위 [진폭](#진폭)).
8. **하루 오차:** `(규격 박간격 / 측정 박간격 − 1) × 86400`. 신뢰구간은 회귀 오차와 시간대별 값의 흩어짐 중 큰 쪽을 씁니다. 시계 자체의 느린 흔들림 때문에 회귀 오차만 쓰면 신뢰구간이 지나치게 좁게 나오기 때문입니다.

## 검증

`tests/`의 합성 녹음(도시 소음, 레버 소리, 비트 에러, 강약 틱, 언락 소리 포함)에서 하루 오차는 정답과 0.5초/일 이내, 진폭은 8° 이내로 맞습니다.
실제 녹음(Slava 5671)에서는 Android 타임그래퍼 앱 측정값(+7초/일)과 이 도구의 값(+8.4 ± 0.6초/일)이 일치했습니다.

python3 -m pytest
```

```

  audio.py      오디오 읽기(ffmpeg), 소음 제거, 소리 크기 곡선

  cli.py        명령줄 (clock-rate)
tests/          합성 신호 테스트
